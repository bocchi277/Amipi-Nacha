System Usage Guide & NACHA Rules

            
            

              

                1. Batch 1 Upload & QuickBooks Support:
                

                  Supports QuickBooks Desktop payment exports (.xlsx) and standard tabular files (.csv, .xlsx). The parser automatically extracts vendor names, amounts, invoice numbers, and matches against active database vendors.
                

              


              

                2. Batch 2 Manual Payment Entry:
                

                  Allows direct manual entry of payment items linked to registered vendors in the Vendor Book. Live duplicate checking flags identical payments (same vendor, amount, invoice ref, and effective date) and provides an explicit override option.
                

              


              

                3. Combined NACHA Transmit File Specifications:
                

                  Generates 94-character fixed-width NACHA flat files complying with Chase CCD Credit specifications. Automatically computes entry counts, batch counts, block counts, entry hash checksums, and total credit amounts.
                

              


              

                4. Vendor Directory & Bank Detail Change Approvals:
                

                  Standard users can view active vendor bank details and submit change requests. Bank detail updates enter a PENDING state and require explicit Admin Review approval before mutating PostgreSQL records.
                

              


              

                5. Transaction History & Remittance Email Notifications:
                

                  All payment transactions record vendor remittance entries. Users can filter by vendor, status, or date range, select multiple items, and trigger bulk email dispatches with an explicit confirmation step.
                

              

            

          


          
          

            
Field Technical Specifications & Validation Rules

            

              

                
                  

                    Field Name
                    NACHA Standard
                    Validation & Formatting Rules
                  

                
                
                  

                    Routing Number
                    9 Digits
                    Must be a valid 9-digit ABA routing number passing the Modulus 10 checksum algorithm (e.g., 021000021).
                  

                  

                    Account Number
                    Up to 17 Chars
                    Must preserve leading zeros. In spreadsheets, format account cells as TEXT to avoid truncation.
                  

                  

                    Account Type
                    Checking / Savings
                    Transaction code 22 for Checking credits; transaction code 32 for Savings credits.
                  

                  

                    Invoice / ID Reference
                    15 Chars Max
                    Alphanumeric reference string. Auto-populated with invoice reference or last 6 non-zero account digits if left blank.
                  

                  

                    Reserved Keywords
                    Disallowed
                    Chase CCD Credit guidelines strictly prohibit reserved terms PAYROLL and REVERSAL in entry descriptions.
